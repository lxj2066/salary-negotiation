# 加薪谈判 · Skill 包

把「我想涨薪」变成「这件事按公司逻辑应该批，批多少、凭什么、退到哪」。

本仓库是一份「加薪申请 Agent」System Prompt 的**审计重铸版**：保留原版由头分类与护栏，补上它缺的定价算法、取证方法、退路设计。

## 这套东西解决什么

原提示词在「怎么说得体」上是专业水准：六类由头、分场景分企业类型、先口头后书面、四类禁用句式，骨架都对。但它有三个空档，恰好是谈判真正分胜负的地方。

| 原病 | 拦截方式 |
|---|---|
| 反复要求「给区间」，全篇没有一处说区间怎么算 | 三锚定价（带宽分位 / 增量折算 / 替换成本）+ `salary_calc.py`，模型不口算 |
| 硬规则禁编数据，但用户就是没有数字，只能输出一屏 `[待补充]` | 无数字降级法：动作 + 对象 + 可核实结果；翻译不出就直说时机不成立 |
| 内部矛盾：硬规则 6 禁比较，模板 B 却把「年限长」写成适用条件 | 统一口径：年限不作由头，改写为职责累积的时间证据 |
| 挡回话术只覆盖 3 种，真实高频有 7 种 | 七类挡回三层表：挡回原话 → 真实含义 → 应答 |
| 问了「谁能批」，拿到答案后没有下一步 | 决策链地图：提报人 / 审核人 / 签字人 / 否决点，附「绕过直属领导成功率更低」的机制解释 |
| 结构收益四类并列，等于给 HR 一张低成本换高成本的菜单 | 按兑现确定性五级排序，口头承诺必须书面化 |
| 被拒后只有「约定再谈」，没有节点 | 30/60/90 复谈日历，D+3 确认邮件是核心动作 |
| 没有 BATNA 自评，用户误判手里的牌 | 三维修强弱判断 + 强弱对应策略 |
| 邮件只给结构不给文本，用户还得自己写 | 四个可直接填空的完整模板 + 主题行三策略 |
| 口头沟通只设计了成功路径，没说当场被否怎么办 | 三步：不接结论 / 要依据 / 留钩子 |
| 六模块输出上千字，见领导前 3 分钟看什么 | 5 分钟速览卡，五个空格 |
| 年龄、婚育、家庭负担影响策略但没隔离规则 | 敏感变量只进内部判断，永不进对外文本 |
| 国企只说「难」，没给路径优先级 | 职级晋升 > 专项奖励 > 岗位津贴 > 底薪调整 |

完整审计报告见 [`salary-negotiation-skill/references/audit-report.md`](salary-negotiation-skill/references/audit-report.md)，14 项按 P0/P1/P2 分级。

## 三个确定性脚本

```bash
# 三锚定价：给出开口锚 / 目标锚 / 底线锚
python salary-negotiation-skill/scripts/salary_calc.py \
  --current 20000 --scene role --firm private \
  --band-min 15000 --band-mid 22000 --band-max 28000 --increment 600000
```

```
开口锚 Ask    30,100 元   ← 第一次报这个数
目标锚 Target 25,500 元   ← 心里真实目标，不主动说
底线锚 Walk   22,000 元   ← 低于此值改谈结构收益

目标涨幅      27.5%   该由头经验区间 10%—25%
结构收益缺口  3,500 元/月（42,000 元/年）
```

```bash
# 交付前预检：拦五类硬伤
python salary-negotiation-skill/scripts/preflight.py --file out.md --facts 20000,25000
```

## 三条边界

1. **不承诺结果**。不保证能谈成。保证的是：你报的数有依据，对方压价时必须给理由。
2. **不做法律判断**。欠薪、违法调岗、变相降薪超出本包范围。
3. **数字都是你的**。脚本里的经验区间是行业经验值，不是市场行情，也不是承诺。所有具体数字必须来自用户输入。
