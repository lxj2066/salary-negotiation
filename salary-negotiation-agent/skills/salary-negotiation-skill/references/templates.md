# 邮件模板库：四个可直接填空的版本 + 主题行策略 + 速览卡

原提示词只给了「正文结构」（职责概述 → 项目 → 对标 → 期望），用户拿到的是骨架，还得自己写。这里给完整文本，只留空格让人填。

**共用纪律**：
- 250 字内。超过 250 字，对方读的是摘要，你的重点会被稀释。
- 一段一件事，不并列超过三项。
- 不出现四类禁用句式（卖惨 / 比较 / 威胁 / 年限）。
- 每个数字后面都能追到出处。填不出的空格留着，不许自己补。

---

## 主题行策略（先定主题，再写正文）

主题行决定这封邮件被归到哪一类、什么时候被打开、被谁转发。三种场景三种策略：

| 策略 | 主题行 | 适用 |
|---|---|---|
| 中性稳妥 | `关于薪酬调整的沟通 — {姓名}` | 关系好、流程顺、不想显得急 |
| 带锚点 | `关于{A项目}交付后职责与薪酬的沟通 — {姓名}` | 有硬成果，让对方一眼看到由头 |
| 走流程 | `薪酬调整申请 — {姓名} — {2026Q4}` | 大公司、需要归档、HR 要编号 |

**禁忌**：`加薪申请`（太直白，容易被当成情绪诉求）；`关于我个人发展的沟通`（模糊，会被约到别的话题）；带感叹号或问号的主题。

---

## 模板 A · 数据型（有硬成果，最稳）

```
主题：关于{A项目}交付后职责与薪酬的沟通 — {姓名}
备选：关于薪酬调整的沟通 — {姓名}

{领导称呼}：

想就我的薪酬安排和您沟通一次。

过去一年我主要负责{A业务}，核心是{一句话说清你的角色}。
其中{项目/事项}带来了{可核实结果，如：X 万增量收入 / 周期从 X 压到 Y / 客户续约 N 次}，
这块不在我岗位最初的目标范围内。

同时我的职责从{入职时范围}扩展到{现在的范围}，
新增了{具体新增的 1—2 项}，团队未增编。

参考同类岗位在市场上的区间（{X—Y}，来源：{招聘平台/JD/同行信息}），
结合我当前的职责范围，希望能将月薪从{现有}调整到{目标区间}。

具体时间与方式听您安排。方便的话，本周找 20 分钟当面聊一次。

{姓名}
{日期}
```

**为什么这样写**：第二段给结果，第三段给职责变化，第四段才给数字。顺序不能反——先给数字，对方会直接从数字开始砍；先给依据，对方要先处理依据。

## 模板 B · 保守型（成果不突出、职责稳增）

**注意**：原版这个模板的适用条件写的是「年限长」，与「不比较」的硬规则冲突。改后口径：**不写年限，写职责累积的时间证据。**

```
主题：关于薪酬调整的沟通 — {姓名}
备选：关于岗位职责与薪酬的沟通 — {姓名}

{领导称呼}：

想和您沟通一下我的薪酬安排。

我在{岗位}上主要负责{核心职责}，过去一段时间保持了{稳定交付的具体表现，
如：连续 N 个季度按时交付 / 客户投诉为零 / 接手后未出现延期}。

这期间我的职责有过几次扩展：{时间点}接手了{事项 A}，
{时间点}开始负责{事项 B}，目前实际覆盖的范围已经超出最初的岗位描述。

我理解公司在薪酬上有整体节奏和预算安排，也愿意配合。
如果今年的空间有限，我想了解按什么标准可以在下一个节点重新评估。

方便的话，想约您 15 分钟当面聊。

{姓名}
{日期}
```

**关键改动**：不写「我干了八年」，写「这期间职责有过几次扩展：X 月接手 A，Y 月开始负责 B」。同样的事实，一个是被动资历，一个是主动增量。

## 模板 C · 成果汇报型（晋升答辩 / 述职 / 公司要求书面材料）

```
主题：{姓名} — {2026年度}岗位履职与薪酬调整说明

一、岗位价值匹配
{岗位}在{业务线}中承担{价值定位，一句话}。

二、履职演进
入职时：{A}
现在：{A + B + C}（{时间点}起新增 B，{时间点}起新增 C）

三、阶段性成果
1. {成果一，带可核实结果}
2. {成果二}
3. {成果三}

四、下一阶段规划
{未来 6—12 个月要做的 2—3 件事，与公司目标挂钩}

五、薪酬调整说明
结合职责范围与市场区间（{X—Y}），申请将月薪由{现有}调整至{目标区间}。

{姓名}
{日期}
```

**用途**：即使不批，这份材料也是一份专业底稿，可以直接进晋升材料或年度述职。**不批也留下资产**，这是这个模板的真正价值。

## 模板 D · 有外部 offer（特殊，谨慎）

**使用前提**：用户已经决定要走，或对方主动问起。**不主动用 offer 施压。**

```
主题：关于近期沟通的跟进 — {姓名}

{领导称呼}：

有件事想坦诚和您说一下。

最近有外部机会找到我，条件比现在有吸引力。
但我在这里做了{时长/项目}，对团队和手上的事有真实投入，
所以在做决定前，想先了解公司这边是否有匹配或部分匹配的可能。

无论结果如何，我都会把手上的事交代清楚，也会提前足够时间沟通。

如果方便，想约您聊 20 分钟。

{姓名}
{日期}
```

**红线**：
- 不写「如果不能满足我将……」
- 不写具体 offer 数字（写数字就变成比价，话题立刻从「留人」变成「值不值这个价」）
- 必须同时给用户一条**不用 offer 的替代表达**（见 `references/talk-tracks.md`「不用 offer 的等价表达」）

## 被拒后第一句（四个可直接用的版本）

这句话只有一个功能：**把当场反应的权利要回来。** 你不需要在被拒的三十秒内表现得体面、豁达、专业。

| 场景 | 第一句 | 为什么这么说 |
|---|---|---|
| 对方明确拒绝 | 「我需要想一下，能不能明天再跟您聊十分钟？」 | 争取一个晚上，避免当场争辩或退让 |
| 对方说「再看看」 | 「行。那我什么时候来问您进展比较合适？」 | 把模糊承诺变成一个日期 |
| 对方说「预算没了」 | 「理解。那下个窗口大概什么时候开？我提前准备。」 | 不争总量，锁下一个时点 |
| 对方当场给了难听的话 | 「我记下了，我回去想想怎么调整。」 | 不辩解，不接火，保住关系 |

**四条共同点**：都是请求（要时间、要信息、要日期），都不是表态。表态（「我理解」「那我再努力」）会当场关掉话题，请求不会。

**禁忌**：
- ❌「好的，我理解」——这句话说出口，门就关了一半
- ❌「那我能问一下为什么吗」——当场追问原因，容易变成辩论
- ❌「没关系，我再等等」——把主动权全部交出去

## 5 分钟速览卡（见领导前看这一张）

六件套加起来一千多字，但真实场景是：用户在会议室门口，只有三分钟。所以每次输出末尾都要附这张卡，让用户能抄在手机备忘录里。

```
┌─ 见领导前速览 ─────────────────┐
│ 主由头：______________________  │
│                                 │
│ 开口：______  目标：______      │
│ 底线：______                    │
│                                 │
│ 必说一句：____________________  │
│ 绝对不说：____________________  │
│ 如果被当场否：________________  │
└─────────────────────────────────┘
```

填写规则：
- **主由头**：一句话，不带修饰。例：「职责从投放扩到投放+私域+复购，团队没加人」
- **开口 / 目标 / 底线**：三个数，来自脚本输出，不现场改
- **必说一句**：这场谈话如果只能记住一句，是哪句。通常是主由头的降级表述
- **绝对不说**：这场谈话最容易脱口而出的那句错话。通常是卖惨或威胁
- **如果被当场否**：从上面「被拒后第一句」四版里选一条抄进来。这一行是整张卡的保险丝

这张卡的作用不是提醒，是**限制**。人在紧张时会说多余的话，一张只有六个空格的卡，能物理性地减少多余的话。

- [ ] 主题行选了哪种策略，是不是最合适的那一种？
- [ ] 正文是否 250 字内？
- [ ] 每个 `{ }` 都填了，或者明确标了 `[待补充]`？
- [ ] 有没有出现「我干了 N 年」「同事都」「我压力大」「不给就走」？
- [ ] 数字能不能追到出处（用户原话或脚本输出）？
- [ ] 有没有一句「方便的话约 X 分钟当面聊」——没有这句，邮件就变成单向申请？
