# 涨幅定价模型：三锚定法与三档区间

原提示词反复要求「给区间」，但没给算法。这份文件补的就是算法。

**一条纪律**：所有数字由 `scripts/salary_calc.py` 算出，模型不口算区间。脚本不可用时才用手算表（本文末），并在交付里注明「本次未用脚本」。

---

## 一、为什么必须是三锚，不能是一个数

只给一个数，谈判就变成「接受或拒绝」的二选一，你必然被压。三锚的作用是**把单点谈判变成区间谈判**：

| 锚 | 是什么 | 谁说出来 |
|---|---|---|
| 开口锚 Ask | 第一次报的数，高于真实目标 | 你主动说 |
| 目标锚 Target | 你真正想拿到的值 | 不说，只用来判断对方还价是否可接 |
| 底线锚 Walk-away | 低于此值不接，改谈结构 | 不说，只在心里 |

报 Ask 不是为了拿 Ask，是为了让对方的还价落回 Target 附近。**没有 Ask，对方就从 Target 往下砍。**

---

## 二、锚 A · 内部带宽分位

### 需要的信息

带宽 `[下限 L, 中位 M, 上限 U]`。用户常不知道，可从三处推：
- 招聘 JD 上写的薪资范围（通常就是 L—U，中位是 M 的近似）
- 同岗位新人的 offer 范围（最准，但要注意保密）
- 公司薪酬制度文件或职级对照表（大公司内网常有）

### 算法

```
当前位置分位 pos = (现有薪资 − L) ÷ (U − L)
```

| pos 区间 | 定位 | 目标算法 | 配套主由头 |
|---|---|---|---|
| pos < 0.50 | 低于中位 | Target = M × 1.05 | 职级带宽内校准 |
| 0.50 ≤ pos < 0.75 | 中位到 75 分位 | Target = 现有 × 1.10 | 职责扩展 |
| pos ≥ 0.75 | 接近上限 | 底薪空间已尽，转结构收益 | 关键人才保留 + 结构收益 |

**上限硬约束**：Target 不得超过 U。超了就说明这不是加薪问题，是**职级问题**——该谈晋升，不该谈涨薪。

### 为什么低于中位时用 M×1.05 而不是 M

直接要中位，等于要求公司承认当初定级偏低，这是让人认错，阻力最大。要中位上方一点点，对方可以说「校准到中位偏上」，是个体面的说法。**给对方留台阶，是让流程能走下去的技术动作。**

## 三、锚 B · 增量产出折算

### 算法

```
目标年化增量 = 用户提供的增量收益 × 分享比例
Target(B) = 现有月薪 + (目标年化增量 ÷ 12)
```

### 分享比例（经验区间，非精确值）

| 增量性质 | 分享比例 | 理由 |
|---|---|---|
| 直接收入创造（销售、BD、投放 ROI） | 20%—25% | 归因清晰，可核算 |
| 成本节省 / 效率提升 | 15%—20% | 归因较清晰，但有协同因素 |
| 风险规避 / 客户留存 | 10%—15% | 归因难，易被质疑「本来也不会出事」 |
| 支持职能（HR、财务、行政） | 10%—15% | 间接贡献，需转成业务语言 |

### 前提：必须是可持续增量

**一次性的钱不进底薪。**

一个项目带来的一次性收益，正确的兑现方式是项目奖或一次性奖励；底薪只承接能年年发生的东西。把一次性收益永久化，有两个后果：对方会用制度直接回绝（「这个不能进 base」），以及你会显得不懂规则——而「不懂规则」这个印象，比要价高更伤人。

判据：**这件事明年还会发生吗？** 会 → 进底薪。不会 → 走奖金，同时在谈话里说明「我知道这是一次性的，所以我想谈的是奖金分配，不是底薪」。

脚本参数：`--increment-type recurring`（默认，进底薪）/ `oneoff`（走奖金，锚 B 跳过）。

**写邮件时用绝对值，不写比例。** 「带来 120 万增量，希望薪酬有相应体现」比「按 20% 分成我要 24 万」安全得多——后者会让对方立刻开始跟你算账，而算账的主动权在他手上。

## 四、锚 C · 替换成本倒推（必须有市场价）

### 为什么旧公式是错的

一个常见的错误算法是：`替换成本 = 现有薪资 × 7.5 个月`，然后推出 `Target = 现有 × 1.31`。

这个公式**不含任何关于你的信息**。不管你年入二十万还是八十万，不管是核心骨干还是可替换岗位，它都给出 +31%。这不是定价，是给现有薪资乘一个常数——它叫伪锚。

替换成本的真实含义是「公司换掉你要花多少钱」，而这件事**只取决于外部市场价**，不取决于你现在拿多少。

### 算法

```
替换年成本 = 市场月薪 × 12 × (1 + 20% 招聘成本) + 市场月薪 × 上手折损月数
Target(C)  = 现有月薪 + (替换年成本 − 现有年薪) × 0.5 ÷ 12
```

- 招聘成本 20%：猎头费（20%—25%）、面试与流程时间成本
- 上手折损默认 3 个月：新人前 3 个月通常只有 50%—70% 产出，取半产能即 1.5 个月全额，加上学习曲线，按 3 个月计
- 系数 0.5：公司为避免这笔支出，理性上最多愿付其中一半来留人

### 三种情况

| 情况 | 判断 | 处置 |
|---|---|---|
| 没给市场价 | 算不出 | 锚 C 弃用，明确说「替换成本必须由市场价推出」 |
| 市场价 < 现薪 | 你在外部拿不到现在的价 | 「市场对标」这条路不成立；但锚 C 仍可算（它衡量公司换人的代价，不是你的市场价） |
| Target(C) ≤ 现薪 | 替换你比留你便宜 | 「关键人才保留」由头不成立，锚 C 弃用 |

### 使用纪律

- 这个值**是上限参考，不是建议值**。它回答「公司最多能忍到哪」，不是「你应该要多少」。
- 只有主由头是「关键人才保留」时才启用。
- 表达时用经济账，不用威胁：「换人大概 6 到 9 个月成本」是替公司算账；「所以你得给我涨」是替自己开价。前者有效，后者归零。

### 替换成本的三个组成（用户可自己核）

| 项 | 估算 | 说明 |
|---|---|---|
| 招聘成本 | 年薪 15%—30% | 含猎头费（20%—25%）、面试时间成本 |
| 上手期折损 | 3—6 个月产能 | 新人前 3 个月通常只有 50%—70% 产出 |
| 隐性成本 | 难估 | 客户关系断档、项目延期、团队补位加班 |

公开人力资本研究常把总替换成本估为 **6—9 个月薪资**。这是区间估计，引用时说「通常估计」。

## 五、加权与三档

### 加权规则

- **有带宽**：A 权重 0.5，B 0.3，C 0.2。缺哪锚，权重按剩余比例重分配。
- **无带宽**：B、C 各 0.5。缺一锚则单锚直用，并在输出里注明「单锚定价，区间偏保守」。
- **用户自己给了期望涨幅**：用用户的数作 Target，但必须跑匹配检查（见第六节），不匹配就提醒。

### 三档

| 档 | 算法 | 硬约束 | 用途 |
|---|---|---|---|
| 开口锚 Ask | Target × ask_mult | **≤ 带宽上限 U** | 第一次报的数 |
| 目标锚 Target | 加权值 | ≤ 带宽上限 U、≤ 该由头经验上限 | 心里真实目标 |
| 底线锚 Walk-away | Target × 0.65 | **≥ 现有 × 1.03，≤ Target × 0.85** | 低于此值改谈结构收益 |

### 开口倍数 ask_mult

| 企业类型 | ask_mult | 理由 |
|---|---|---|
| 民企 / 成长型 | 1.15—1.20 | 决策链短，会直接砍价，需留空间 |
| 外企 / 成熟体系 | 1.10 | 走带宽与分位逻辑，虚高会被判定不专业 |
| 国企 / 体系内 | 1.05 或改走津贴 | 工资总额管控，虚高无效 |
| 不确定 | 1.10 | 按流程严格型保守处理 |

### 两条约束的理由（这两条比倍数重要）

**开口锚不得超带宽上限。** 报一个超出岗位上限的数，在体系内的正确解读不是「他有底气」，是「他不懂我们怎么定价」。专业度一旦被扣，后面每一句都会被重新打折。超出上限的诉求不是报价问题，是职级问题或结构收益问题——换个战场，别在报价上硬顶。

**底线锚不得高于 Target × 0.85。** 底线一旦抬到接近目标，谈判空间就被压成一条缝，对方稍微压一点就击穿，你只能全盘接受或当场翻脸。底线的作用是让你知道「什么时候该换战场」，不是让你「守住一个数」。

**底线锚不得低于现有 × 1.03。** 低于这个数，这次申请就不值得消耗——一次正式申请被拒，同一个由头半年内基本不能再用。

### 旧版「底线不低于带宽中位」为什么被改掉

原规则是「Walk-away 不低于带宽中位 M」。这条在**当前薪资已经低于中位**时是错的：用户现薪 20000、中位 22000，规则会把底线抬到 22000，等于要求「这次至少涨 10%」——这不是底线，是第二个目标。结果是谈判空间从 5000 缩到 3000，稍微一压就到底。

新规则把「中位」从硬约束降为**参考落点**：底线向中位靠，但必须同时满足「不高于目标 85%」。中位是「理想底线」，不是「必须守住的线」。

## 六、匹配检查（脚本会自动跑）

| 检查 | 触发条件 | 处置 |
|---|---|---|
| 涨幅超由头上限 | 实际涨幅 > 该由头的经验上限 | 警告：换更强由头，或把超出部分转结构收益 |
| Target 超带宽上限 | Target > U | 警告：这是职级问题，不是加薪问题 |
| 开口锚超带宽上限 | Ask > U | 已自动压回上限，并提示超出部分转结构收益 |
| 底线离目标太近 | Walk > Target × 0.85 | 提示：没有谈判空间，先调目标 |
| 底线低于现有 | Walk ≤ 现有 | 提示：目标与现薪过近，构不成谈判空间 |
| 单锚定价 | 只有一锚可用 | 标注「区间偏保守」 |
| 涨幅低于 3% | 实际涨幅 < 3% | 提示：低于此值通常不值得消耗一次申请机会 |
| 用户期望远超上限 | 用户给的 pct > 由头上限 × 1.5 | 提示：大概率被拒，且会影响下次，建议先调预期 |
| 超直属主管授权 | 目标涨幅 > 8% | 提示：他一个人批不了，材料要备成可转发给上级的版本 |
| 市场对标作主由头 | scene = market | 警告：建议降为辅由头 |

## 七、手算表（脚本不可用时）

按顺序填，五分钟能算完：

```
① 现有月薪 ____________
② 现有年薪 = ① × 12 = ____________

③ 带宽：L ______  M ______  U ______
   pos = (① − L) ÷ (U − L) = ______
   pos < 0.5  → Target_A = M × 1.05 = ______
   0.5—0.75   → Target_A = ① × 1.10 = ______
   ≥ 0.75     → 转结构收益，Target_A 不适用

④ 年化可持续增量 ______ × 分享比例 ______ = ______
   Target_B = ① + (④ ÷ 12) = ______
   （一次性增量不进底薪，走奖金，此行跳过）

⑤ 外部同岗市场月薪 MKT = ______
   替换年成本 = MKT × 12 × 1.2 + MKT × 3 = ______
   Target_C = ① + (替换年成本 − ②) × 0.5 ÷ 12 = ______
   无市场价 → 锚 C 不做，不要用 ① × 1.31 代替

⑥ 加权 Target：
   有带宽 → (Target_A × 0.5 + Target_B × 0.3 + Target_C × 0.2) = ______
   无带宽 → (Target_B × 0.5 + Target_C × 0.5) = ______
   缺锚 → 按剩余权重归一

⑦ Ask = Target × ask_mult（民企 1.18 / 外企 1.10 / 国企 1.05）= ______
   ★ Ask 若 > U，压回 U（超出上限的报价在体系内不受理）

⑧ Walk = Target × 0.65 = ______
   ★ 若 < ① × 1.03，抬到 ① × 1.03
   ★ 若 > Target × 0.85，压到 Target × 0.85
   （带宽中位 M 只作参考落点，不作硬约束）

⑨ 缺口 = Target − Walk = ______  ← 这个数就是结构收益要补的额度
```

第 ⑨ 行是最容易被忽略但最有用的一行：**底薪谈不下来时，结构收益不是随便要，是要补上这个缺口。**

第 ⑤ 行是这一版改掉的关键：**没有市场价就不算锚 C。** 用现有薪资乘倍数得到的永远是一个常数，那是伪锚。

## 八、这张表不能做什么

- 不能当市场行情用。锚 A 依赖公司自己的带宽，锚 B 依赖用户自己的产出，锚 C 依赖替换成本估算——**三个都是这家公司、这个人、这个岗位的局部值**，不是行业数据。
- 不能保证被批。它只保证一件事：**你报的数有依据，对方压价时必须给出理由。** 谈判里这已经赢了一半。
- 不能替代预算现实。公司没钱的时候，任何模型都无效，此时唯一有效的是结构收益与时间承诺。
