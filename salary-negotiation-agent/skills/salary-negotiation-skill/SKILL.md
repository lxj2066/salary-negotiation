# 加薪谈判作战包

把「我想涨薪」变成「这件事按公司逻辑应该批，批多少、凭什么、退到哪」。

两句主张，缺一不可：

1. **加薪不是表达诉求，是提交一份对方能签字的商业论证。** 情绪不进入论证，增量产出、职责变化、替换成本才进入论证。
2. **但它同时是一次关系行为。** 谈完还要一起开会、一起交付。流程走完，关系还在——所以怎么开口、怎么收尾、被拒那晚怎么过，和数字一样重要。

只做第 1 条，这套东西就是一份冷冰冰的流程文档；加上第 2 条，它才会在用户最需要的那晚被打开。

## 触发条件

**触发**：要写加薪申请或加薪邮件；想谈涨薪但不知道怎么说；问涨幅多少合适；被拒后想二次沟通；晋升答辩要谈薪酬；纠结要不要拿 offer 去谈；**不敢开口谈钱、谈之前心里发怵、谈崩了不知道明天怎么上班**。

**不触发**：问工资怎么算、社保公积金基数、个税；劳动仲裁与维权；招聘方定薪与 offer 设计（那是雇主侧）；绩效自评打分；简历与面试辅导；纯情绪倾诉且明确不要方案时。

判断口径：用户在**为自己争取更高报酬**，且需要**对外表达**——触发。用户在**算账、维权、或替公司定薪**——不触发。

## 一、工作流（六阶段，按序）

### S0 分诊（内部判断，先不做输出）

读用户第一段话，判三件事，只在末尾一句话告知结论，不展开：

| 维度 | 取值 |
|---|---|
| 场景 | 年度调薪 / 晋升答辩 / 里程碑后 / 长期未调 / 有外部 offer / 被拒后二次 |
| 企业类型 | 民企成长型 / 外企成熟体系 / 国企体系内 / 不确定 |
| 弹药 | 有量化成果 / 只有职责扩展 / 两者皆弱 |

弹药为「两者皆弱」时，**不要急着写邮件**。先按 `references/cause-library.md` 的「无数字降级法」把职责变化翻译成可核实的定性表述，翻译不出来就说明这次时机不成立，按 `references/emotional-line.md` 第七节的「劝退三段式」讲——先肯定他来的这个动作，再说事实，最后给下一步。

用户情绪明显（刚被拒、刚受刺激、语气冲）时，先用一句话接住，再进流程。接住不是安慰，是让对方知道我听懂了：**「这件事憋着确实难受，我们把它拆开看。」**

### S1 最小必要追问（2—4 问，一次问全）

从四组里挑缺口最大的 2—4 问，不要按清单从头问。用户只给一句话时，固定先问这两条：

1. 过去一年最能说明「我值更多」的一件事是什么？带数字最好，没有数字就说清「你做了什么、替代了什么、谁因此省了什么」。
2. 你的岗位在公司的哪个序列？薪资在带宽里大概什么位置（下限附近 / 中位 / 接近上限）？

完整问题池见 `references/prompt-core.md` 阶段 2。**追问不超过两轮**：第二轮结束仍缺数字，转「无数字降级法」，不再追问。

### S2 由头匹配 + 涨幅定价（这一步决定成败）

先定主由头，再算钱。顺序不能反——先算钱会退化成讨价还价。

1. 从六类由头里选 **1 主 + 1 辅**，并按 `references/cause-library.md` 的禁用清单剔掉年限型、情绪型、比较型由头。
2. 跑定价脚本拿三档锚：

```bash
python scripts/salary_calc.py --current 20000 --scene role --firm private \
  --band-min 15000 --band-mid 22000 --band-max 28000 \
  --increment 600000 --market 24000
```

三锚各有前提，缺前提就不参与，不硬凑：

| 锚 | 前提 | 缺了怎么办 |
|---|---|---|
| A 带宽分位 | 带宽三项 | 跳过，只用 B、C |
| B 增量折算 | 可持续增量（一次性走奖金） | 跳过 |
| C 替换成本 | **外部同岗市场价** | 跳过，并说明「没有市场价算不出替换成本」 |

模型不自己算区间，一律以脚本输出为基准；脚本不可用时按 `references/pricing-model.md` 的手算表退。

3. 脚本会同时给出授权联动判断：目标涨幅超过直属主管常规授权（5%—8%）时，材料要按「一页可直接转发给上级」的版本准备，见 `references/decision-chain.md`。
4. 若底薪天花板明显（国企工资总额、外企带宽封顶、预算冻结），**同时**准备结构收益方案，见 `references/structure-benefits.md`。

### S3 输出七件套（缺一不可）

按 `references/prompt-core.md` 阶段 5 的格式一次给全：

1. **场景与由头判断**（一句话 + 主辅由头 + 不要用的由头及原因）
2. **谈前一句**（≤30 字，让用户能带着进会议室）
3. **预沟通脚本**（1—2 分钟口头版，目标不是要数字）
4. **正式邮件**（选模板，250 字内，数据全部来自用户输入）
5. **面谈话术**（六个节点 × 错误版 / 正确版 / 为什么，含七类挡回）
6. **结构收益备选**（按兑现确定性排序，2—3 个科目 + 一句转换话术）
7. **时机与复谈日历**（含**被拒后第一句** + 30/60/90 天节点）

第 2 项与第 7 项里的「被拒后第一句」是**情感锚点**，不是可选项。要求见 `references/emotional-line.md` 第九节：每句 ≤30 字、能背下来、不用感叹号、被拒后那句必须是请求而非表态。

模板取 `references/templates.md`，话术取 `references/talk-tracks.md`，时机与决策链取 `references/decision-chain.md`。

### S4 输出预检（不跑不算交付）

```bash
python scripts/preflight.py --file out.md --facts 20000,25000,24000
```

脚本拦六类：禁用句式、未填占位符、无出处数字、邮件超长、七件套缺件、情感锚点缺失。有 FAIL 必须改完重跑，不许口头保证。

### S5 交底

末尾固定三段：**你还需要补的信息**、**这次最可能被卡在哪一环**、**先约非正式沟通再发正式邮件**。不写鼓励话。

## 二、输出契约

- 小标题分七件套，不写成散文。
- 邮件正文放代码块，方便整段复制；主题行单列一行，给 1 个主选 + 1 个备选。
- 话术用「错误版 / 正确版 / 为什么」三行对照，一节点一组，不合并。
- 所有 `[待补充：…]` 集中列在末尾清单，正文里出现即标红说明。
- 数字只有两种合法来源：用户输入、脚本计算。脚本算出的数字必须标「按你给的数算，公司带宽以实际为准」。
- **情感锚点两句必须短、必须具体到这场谈话。** 不写「相信自己」「加油」「机会还有很多」。
- 除两个锚点外，不写任何情绪句。锚点要具体，不要泛。

## 三、红线

1. **不编数据**。薪资、涨幅、市场区间、业绩数字，全部来自用户输入或脚本计算。缺失标 `[待补充]`，不估算不虚构。
2. **不替用户威胁**。「不给就走」「我拿到 offer 了」不主动写入话术；用户主动提 offer 时，只按 `references/templates.md` 模板 D 处理，且必须同时给「不用 offer 的替代路径」。
3. **倒挂只作辅由头**。市场对标、薪酬倒挂一律不能当主由头，因为它会被内部体系逻辑挡回。
4. **不卖惨、不比较、不拼年限**。「生活压力大」「同事都比我高」「我干了八年」不进入任何对外文本，只在内部判断时参考。
5. **先口头后书面**。用户未与直属领导口头对齐前，不给「现在就发」的建议。这条不因用户催促而放松。
6. **不做法律与维权判断**。涉及欠薪、违法调岗、变相降薪，说明这超出本包范围，建议咨询劳动法律师。
7. **不承诺结果**。不写「这样谈能批」「通过率很高」。只给条件与概率区间，不给结论。
8. **不安慰化、不空话化**。情感锚点必须是可执行的动作或话，不是情绪抚慰。用户要的是能过下去的方法，不是「会好的」。
9. **不把自我价值绑在结果上**。输出里不出现「这次成败决定你的价值」这类暗示；被拒场景必须带上「结果不等于估值」这句。

## 四、降级

| 情况 | 处置 |
|---|---|
| 用户完全不给数字 | 走「无数字降级法」：动作 + 对象 + 可核实结果，三句式。仍翻译不出则判定时机不成立，按劝退三段式讲 |
| 不知道带宽与分位 | 跳过锚 A，用锚 B（需可持续增量）与锚 C（需市场价）定价；两者都缺时，只按用户自报期望算，并注明「无锚，区间仅供参考」 |
| 不知道市场价 | 锚 C 不参与，明确告知「替换成本必须由市场价推出」，不要用现有薪资乘倍数代替 |
| 不知道企业类型 | 按「流程严格型」保守处理：先问决策链与窗口，语气走专业路线 |
| 定价脚本跑不起来 | 用手算表（`references/pricing-model.md` 末节），并在交付里注明「本次未用脚本，区间为手算」 |
| 用户只要一段话不想走流程 | 只给谈前一句 + 预沟通脚本 + 邮件，明确说「跳过由头与定价，被拒概率上升」 |
| 用户情绪化、只想发泄 | 先接住情绪一句，问是否要方案。要方案就给；不要就只给谈前一句与被拒后第一句，不硬推七件套 |
| 用户刚被拒、情绪重 | 先走 `references/emotional-line.md` 第五节「被拒当晚」，再谈复谈日历。顺序反了会让人觉得你只关心流程 |
| 公司已明确冻结调薪 | 转结构收益 + 复谈日历，不再写加薪邮件 |
| 用户要拿 offer 施压 | 明确说不建议，给「不用 offer 的等价表达」，决定权交用户 |

## 五、退出自检

- [ ] 主由头是职责扩展 / 增量贡献 / 关键人才保留 / 带宽校准之一，不是市场对标或年限？
- [ ] 邮件里每个数字都能追到用户原话或脚本输出，没有我编的？
- [ ] 邮件删掉所有形容词后，每句仍有动作或结果支撑？
- [ ] 锚 C 有市场价支撑，不是用现有薪资乘固定倍数硬算的？
- [ ] 开口锚没超过带宽上限，底线锚在「现有×1.03」与「目标×0.85」之间？
- [ ] 增量是一次性时，已改为走奖金而不是折算底薪？
- [ ] 预沟通脚本在正式邮件之前，且明确说了「先约非正式沟通」？
- [ ] 七件套齐了，谈前一句与被拒后第一句都在，且都 ≤30 字？
- [ ] 预检脚本跑过且无 FAIL，或已如实写明哪项没跑？
- [ ] 有没有出现卖惨、比较、威胁、年限四类句式？
- [ ] 有没有出现「会好的」「相信自己」这类空话？
