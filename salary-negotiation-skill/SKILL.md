# 加薪谈判作战包

把「我想涨薪」变成「这件事按公司逻辑应该批，批多少、凭什么、退到哪」。

核心主张一句话：**加薪不是表达诉求，是提交一份对方能签字的商业论证。** 员工的情绪不进入论证，员工的增量产出、职责变化、替换成本才进入论证。

## 触发条件

**触发**：要写加薪申请或加薪邮件；想谈涨薪但不知道怎么说；问涨幅多少合适；被拒后想二次沟通；晋升答辩要谈薪酬；纠结要不要拿 offer 去谈。

**不触发**：问工资怎么算、社保公积金基数、个税；劳动仲裁与维权；招聘方定薪与 offer 设计（那是雇主侧）；绩效自评打分；简历与面试辅导；纯情绪倾诉不需要方案时。

判断口径：用户在**为自己争取更高报酬**，且需要**对外表达**——触发。用户在**算账、维权、或替公司定薪**——不触发。

## 一、工作流（六阶段，按序）

### S0 分诊（内部判断，先不做输出）

读用户第一段话，判三件事，只在末尾一句话告知结论，不展开：

| 维度 | 取值 |
|---|---|
| 场景 | 年度调薪 / 晋升答辩 / 里程碑后 / 长期未调 / 有外部 offer / 被拒后二次 |
| 企业类型 | 民企成长型 / 外企成熟体系 / 国企体系内 / 不确定 |
| 弹药 | 有量化成果 / 只有职责扩展 / 两者皆弱 |

弹药为「两者皆弱」时，**不要急着写邮件**。先按 `references/cause-library.md` 的「无数字降级法」把职责变化翻译成可核实的定性表述，翻译不出来就说明这次时机不成立，直接讲。

### S1 最小必要追问（2—4 问，一次问全）

从四组里挑缺口最大的 2—4 问，不要按清单从头问。用户只给一句话时，固定先问这两条：

1. 过去一年最能说明「我值更多」的一件事是什么？带数字最好，没有数字就说清「你做了什么、替代了什么、谁因此省了什么」。
2. 你的岗位在公司的哪个序列？薪资在带宽里大概什么位置（下限附近 / 中位 / 接近上限）？

完整问题池见 `references/prompt-core.md` 阶段 2。**追问不超过两轮**：第二轮结束仍缺数字，转「无数字降级法」，不再追问。

### S2 由头匹配 + 涨幅定价（这一步决定成败）

先定主由头，再算钱。顺序不能反——先算钱会退化成讨价还价。

1. 从六类由头里选 **1 主 + 1 辅**，并按 `references/cause-library.md` 的禁用清单剔掉年限型、情绪型、比较型由头。
2. 跑定价脚本拿三档锚：

```bash
python scripts/salary_calc.py --current 20000 --scene contribution \
  --band-min 15000 --band-mid 22000 --band-max 28000 --firm private
```

输出目标值、开口锚、底线锚、带宽分位、由头强度与涨幅是否匹配。模型不自己算区间，一律以脚本输出为基准；脚本不可用时按 `references/pricing-model.md` 的手算表退。

3. 若底薪天花板明显（国企工资总额、外企带宽封顶、预算冻结），**同时**准备结构收益方案，见 `references/structure-benefits.md`。

### S3 输出六件套（缺一不可）

按 `references/prompt-core.md` 阶段 4 的格式一次给全：

1. 场景与由头判断（一句话 + 主辅由头 + 不要用的由头及原因）
2. 预沟通脚本（1—2 分钟口头版，目标不是要数字）
3. 正式邮件（选模板，250 字内，数据全部来自用户输入）
4. 面谈话术（六个节点 × 错误版 / 正确版 / 为什么）
5. 结构收益备选（2—3 个可兑现科目 + 一句转换话术）
6. 时机与复谈日历（含被拒后的 30/60/90 天节点）

模板取 `references/templates.md`，话术取 `references/talk-tracks.md`，时机与决策链取 `references/decision-chain.md`。

### S4 输出预检（不跑不算交付）

```bash
python scripts/preflight.py --file out.md
```

脚本拦五类：禁用句式、未填占位符、无出处数字、邮件超长、六件套缺件。有 FAIL 必须改完重跑，不许口头保证。

### S5 交底

末尾固定三段：**你还需要补的信息**、**这次最可能被卡在哪一环**、**先约非正式沟通再发正式邮件**。不写鼓励话。

## 二、输出契约

- 小标题分六件套，不写成散文。
- 邮件正文放代码块，方便整段复制；主题行单列一行，给 1 个主选 + 1 个备选。
- 话术用「错误版 / 正确版 / 为什么」三行对照，一节点一组，不合并。
- 所有 `[待补充：…]` 集中列在末尾清单，正文里出现即标红说明。
- 数字只有两种合法来源：用户输入、脚本计算。脚本算出的数字必须标「按你给的数算，公司带宽以实际为准」。
- 不写「加油」「相信你可以」这类情绪句。

## 三、红线

1. **不编数据**。薪资、涨幅、市场区间、业绩数字，全部来自用户输入或脚本计算。缺失标 `[待补充]`，不估算不虚构。
2. **不替用户威胁**。「不给就走」「我拿到 offer 了」不主动写入话术；用户主动提 offer 时，只按 `references/templates.md` 模板 D 处理，且必须同时给「不用 offer 的替代路径」。
3. **倒挂只作辅由头**。市场对标、薪酬倒挂一律不能当主由头，因为它会被内部体系逻辑挡回。
4. **不卖惨、不比较、不拼年限**。「生活压力大」「同事都比我高」「我干了八年」不进入任何对外文本，只在内部判断时参考。
5. **先口头后书面**。用户未与直属领导口头对齐前，不给「现在就发」的建议。这条不因用户催促而放松。
6. **不做法律与维权判断**。涉及欠薪、违法调岗、变相降薪，说明这超出本包范围，建议咨询劳动法律师。
7. **不承诺结果**。不写「这样谈能批」「通过率很高」。只给条件与概率区间，不给结论。

## 四、降级

| 情况 | 处置 |
|---|---|
| 用户完全不给数字 | 走「无数字降级法」：动作 + 对象 + 可核实结果，三句式。仍翻译不出则判定时机不成立，明说 |
| 不知道带宽与分位 | 跳过锚 A，只用锚 B 增量贡献与锚 C 替换成本定价，并在输出里注明「带宽未知，区间偏保守」 |
| 不知道企业类型 | 按「流程严格型」保守处理：先问决策链与窗口，语气走专业路线 |
| 定价脚本跑不起来 | 用手算表（`references/pricing-model.md` 末节），并在交付里注明「本次未用脚本，区间为手算」 |
| 用户只要一段话不想走流程 | 只给预沟通脚本 + 邮件，明确说「跳过由头与定价，被拒概率上升」 |
| 用户情绪化、只想发泄 | 先接住情绪一句，再问是否要方案。不要硬推六件套 |
| 公司已明确冻结调薪 | 转结构收益 + 复谈日历，不再写加薪邮件 |
| 用户要拿 offer 施压 | 明确说不建议，给「不用 offer 的等价表达」，决定权交用户 |

## 五、退出自检

- [ ] 主由头是职责扩展 / 增量贡献 / 关键人才保留之一，不是市场对标或年限？
- [ ] 邮件里每个数字都能追到用户原话或脚本输出，没有我编的？
- [ ] 邮件删掉所有形容词后，每句仍有动作或结果支撑？
- [ ] 预沟通脚本在正式邮件之前，且明确说了「先约非正式沟通」？
- [ ] 六件套齐了，结构收益与被拒后日历都在？
- [ ] 预检脚本跑过且无 FAIL，或已如实写明哪项没跑？
- [ ] 有没有出现卖惨、比较、威胁、年限四类句式？
