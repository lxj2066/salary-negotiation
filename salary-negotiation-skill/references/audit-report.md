# 审计报告：这套加薪提示词从雇员视角还差什么

审计对象：用户提供的「加薪申请 Agent」System Prompt 全文。
审计视角：**职场雇员本人**（不是 HR，不是雇主）。判据只有一条——**这份提示词能不能帮一个普通员工把申请谈到批，而不是把邮件写漂亮。**

结论先给：**骨架是对的，缺的是定价、取证、退路。** 原提示词在「说什么」上做得很好（由头分类、话术对照、护栏自检都是专业水准），但在「要多少」「凭什么证明」「不批怎么办」三处是空的。这三处恰好是谈判真正分胜负的地方。

分级口径：P0 = 不改则包不成立；P1 = 不改则实战中会被打回；P2 = 改了更好用。

---

## P0：结构性缺口（4 项）

### 1. 有「给区间」的要求，没有「区间怎么算」的算法

**原病**：全文出现 5 次「给区间」「锚定带宽内合理区间」「涨幅宜稳健」，但从头到尾没有一处说这个区间怎么得出。Agent 只能凭语感编一个数，或者反问用户「你想要多少」——后者等于把最专业的那部分工作退回给最不专业的人。

**为什么致命**：雇员在谈判里最容易被击穿的一句话是「你的依据是什么」。答不出数字来源，后面所有话术都变成求情。而「开口锚 / 目标锚 / 底线锚」三档结构是谈判的标准配置，缺了它，用户只有「一个数」，一被压就只能全退。

**改法**：引入**三锚定价**——锚 A 内部带宽分位、锚 B 增量产出折算、锚 C 替换成本倒推。三锚取加权，再按企业类型调开口倍数（民企 1.15—1.20，外企 1.10，国企 1.05 或改走津贴）。区间必须写成三档，且底线锚不得低于带宽中位。

**落点**：`references/pricing-model.md` + `scripts/salary_calc.py`（模型口算会飘，交给脚本）。

### 2. 「不得编造数据」写死了，却没给「用户就是没有数字」的出路

**原病**：硬规则 1 说缺失处标 `[待补充]`。规则本身对，但真实场景里 70% 的雇员根本拿不出 ROI、成本节省这类硬数字——他们的工作是「把事推进了」「接了一摊原本没人管的活」「客户没跑」。按原提示词执行，输出会变成一张布满 `[待补充]` 的表格，用户一个字都发不出去，转头就弃用。

**为什么致命**：这不是严谨，这是把「我不能编」当成了「我不用干活」。雇员的真实约束是「没有数字但确实多干了」，提示词必须给这类事实一条合法的表达通道。

**改法**：补**无数字降级法**，三句式——`动作 + 对象 + 可核实结果`。例：
- 「带新人」→「承担 2 名新人的 onboarding 与带教，把独立上手周期从 3 个月压到 6 周」
- 「事情变多了」→「从只管投放，扩到投放 + 私域 + 复购，团队没加人」
- 「救了个项目」→「接手延期的 A 项目，在预算内交付，客户续约」

关键判据：**这句话能不能被第三方核实**。能核实就不需要数字，也不需要标 `[待补充]`。同时补一条收敛规则——**追问不超过两轮**，两轮后仍无数字，强制转降级法，不再追问。

**落点**：`references/cause-library.md`「无数字降级法」节 + `SKILL.md` S1/S4。

### 3. 内部矛盾：硬规则禁比较，模板 B 却在用司龄

**原病**：硬规则 6 明令「不比较」，但模板 B（保守型）的适用条件写的是「成果不突出、**年限长**、职责稳增」。年限本质上就是比较——和过去的自己比，和同龄人比。Agent 同时收到两条指令，行为不可预测：可能写出一封「我在公司八年」的邮件，然后自检时又判自己违规。

**为什么致命**：自相矛盾的规则会让模型在关键处随机取舍，而这里取舍错的代价是邮件里出现一句「我干了八年」——这句话在 HR 眼里等于「没有增量」，直接进入最容易被压的一档。

**改法**：统一口径。**年限不作为由头，只作为「职责累积」的时间证据**。改后的表述是：不说「我干了八年」，说「八年里我的职责从 A 扩到 A+B+C，最近一次扩项是 X 月」。同样的事实，一个是被动资历，一个是主动增量。

**落点**：`references/cause-library.md` 禁用清单第 1 条 + `references/templates.md` 模板 B 改写。

### 4. 挡回话术只覆盖 3 种，实际高频有 7 种

**原病**：原提示词只给了「遇预算紧张」「遇画饼」「被拒后」三个节点。真实谈判里 HR 与领导的高频挡回远不止这些，而且每一种的**真实含义**和**破法**都不同。

**为什么致命**：雇员在现场最怕的不是被拒，是**接不住话**。一句「今年普调已经含了你的」就能让人当场哑住，回去才想出怎么答。

**改法**：补七类挡回的「挡回原话 → 真实含义 → 应答」三层表：
1. 「今年普调已经含了你的」→ 真实含义：把你归入常规池，不打算单独立项 → 破法：把话题从「涨幅」移到「序列」，问「我这个岗位在序列里的定位是否还准」。
2. 「你的涨幅已经高于平均了」→ 真实含义：用横向比较封顶 → 破法：不接平均值，接绝对值缺口，问「我现在的绝对值在带宽的哪个位置」。
3. 「公司今年效益不好」→ 真实含义：预算收紧，但不是零 → 破法：不争总量，争排序，问「如果总量有限，倾斜顺序按什么排」。
4. 「再等等，明年一定」→ 真实含义：口头承诺，无成本 → 破法：要条件、要时间、要确认人，三者缺一即为无效承诺。
5. 「你先做出成绩再说」→ 真实含义：把门槛后移 → 破法：当场把「成绩」定义成可验收的三条，落书面。
6. 「你的岗位就是这个价」→ 真实含义：岗位价值判定，不是个人价值 → 破法：转「职责已超出原岗位 JD」，走岗位重估而非个人加薪。
7. 「涨薪要走年度窗口，现在不行」→ 真实含义：流程约束，可能是真的 → 破法：确认窗口时间与提报截止日，当场锁日历。

**落点**：`references/talk-tracks.md`「七类挡回」节。

## P1：实战会被打回（7 项）

### 5. 问了「谁能批」，没给「批不了怎么办」

原提示词问「直属领导自己能批，还是需要往上走」，这是好问题，但拿到答案后没有下一步。真实结构是：直属领导通常只有 5%—8% 的常规调薪权（常见授权区间，以公司授权表为准），超过就得往上走。此时雇员需要的不是「再找大领导」，而是**影响力地图**：谁是提报人、谁是审核人、谁是签字人、谁有一票否决、谁是能影响签字人的第三方。

关键判断：**绕过直属领导直接找上级，成功率远低于让直属领导成为你的提报人。** 提示词必须明确这一条，否则用户会做出最伤关系的动作。

**落点**：`references/decision-chain.md`「决策链地图」节。

### 6. 「判断时机是否合适」没有信号清单

原提示词把时机判断交给模型自由发挥。时机是加薪里权重极高但最容易被忽略的变量——同一个申请，早两周和晚两周结果可能完全不同（预算编制前后、财报发布前后、组织调整前后）。

补正负信号清单：
- **正面**：刚交付里程碑；公司刚融资/财报超预期；直属领导刚升职（有预算与话语权）；年度预算编制前 1—2 个月；团队缺人、招聘冻结（你的替换成本上升）；组织调整后职责重新划分。
- **负面**：公司刚裁员或宣布冻结；领导自己正在被考核；刚被拒不足 3 个月；刚出过事故或绩效评级偏低；跨年预算已锁。

**落点**：`references/decision-chain.md`「时机信号」节。

### 7. 结构收益清单很全，但没排「兑现确定性」

原提示词列了四大类结构收益（现金位移、浮动长期、发展授权、福利），但把它们并列了。这是最危险的一种并列——**期权、虚拟股、发展授权这三类，在雇员侧的兑现概率远低于奖金系数和津贴。** 把它们并列，等于给了 HR 一张「用低成本科目换高成本诉求」的话术地图。

改法：给每个科目打**兑现确定性分级**，并要求 Agent 优先推高确定性科目：

| 确定性 | 科目 | 判据 |
|---|---|---|
| 高 | 现金结构内位移：奖金系数、绩效评优优先级、项目奖金权重、岗位/带教/通讯补贴 | 当期可见、写进制度或考核表即可兑现 |
| 中高 | 项目分红、明确的季度/年度奖励池 | 有分配规则，但依赖业绩达成 |
| 中 | 福利升级：补充医疗、弹性工作、远程天数 | 有预算即兑现，无预算即空 |
| 低 | 期权、虚拟股、利润分享 | 依赖退出机制与估值，3 年内难兑现 |
| 最低 | 发展授权、储备干部、核心项目主导权 | 无书面即无约束，口头等于零 |

硬规则：**口头承诺必须书面化**。任何非现金科目，Agent 都要给一句「把它写进考核表/邮件确认/会议纪要」的动作，否则不算谈成。

**落点**：`references/structure-benefits.md`。

### 8. 被拒后只有「约定再谈」，没有日历

原提示词说「约定达到什么标准、何时、由谁确认再谈」，方向对，但没给节点。真实场景里，「下次再谈」在 90% 的情况下等于「永远不谈」——因为没有时间锚点，双方都不会主动重启。

改法：**复谈日历 30/60/90**：
- **D+3**：发一封确认邮件，把口头共识写成三条（标准、时间、确认人），不催结果，只留记录。
- **D+30**：带一件新交付物做一次 15 分钟短沟通，不谈钱，只更新进展。目的是保持话题活着。
- **D+60**：若承诺标准已达成，正式提复评；未达成则确认差距与调整方向。
- **D+90**：进入下一个窗口的提报准备；若三次无实质进展，评估 BATNA（见第 9 项）。

**落点**：`references/talk-tracks.md`「复谈日历」节。

### 9. 完全没有 BATNA 自评

谈判理论里最基础的一条：**你的底线由你的替代方案决定，不由你的期望决定。** 原提示词让 Agent 直接给区间、给话术，却没让用户先想清楚「这次不谈成，我会怎样」。

这不是鼓励跳槽，恰恰相反——**知道自己的 BATNA 弱，就不该打硬牌**。很多谈崩的案例，都是因为雇员误判了自己手里的牌。

改法：输出前加一段**内部自评**（不写进邮件，只告知用户）：
- 替代方案强度：手上有无真实机会 / 市场对该岗位的需求热度 / 你的技能可迁移性。
- 弱 BATNA 时的策略调整：不打价格牌，改打结构牌与时间牌（争取承诺、争取授权、争取下一次窗口的优先权）。
- 强 BATNA 时的纪律：仍不威胁，只把「我有选择」作为坦诚沟通的背景，不作条件。

**落点**：`references/guardrails.md`「BATNA 自评」节。

### 10. 邮件给了模板，没给主题行策略

主题行决定这封邮件被归到哪一类、什么时候被打开。原提示词四个模板都只给了「主题：关于XX薪酬调整的申请」，实际上三种场景需要三种主题策略：
- **中性稳妥**（关系好、流程顺）：「关于薪酬调整的沟通 — 姓名」
- **带锚点**（有硬成果）：「关于 A 项目交付后职责与薪酬的沟通 — 姓名」
- **走流程**（大公司、要归档）：「薪酬调整申请 — 姓名 — 2026Q4」

**落点**：`references/templates.md`「主题行策略」节。

### 11. 口头沟通当场被否，没有预案

原提示词反复强调「先口头后书面」，但只设计了口头沟通成功的路径。真实高频场景是：你刚开口，领导当场就说「现在不行」「这个我说了不算」「你先把 XX 做好」。

当场被否时最忌两件事：**继续争辩**（把一次沟通变成一次对抗）和**立刻退让**（「好的我理解」等于自己关掉了门）。

改法：给「当场被否三步」——**不接结论、要依据、留钩子**：
1. 不接结论：「我理解，方便的话我想了解一下，主要是卡在预算还是卡在岗位定位？」（把「不行」拆成可处理的原因）
2. 要依据：「如果是预算，今年倾斜的顺序大概是怎么排的？」（拿到排序信息，就有下一次的切入点）
3. 留钩子：「那我按您说的这个方向做，三个月后我再来跟您对一次，可以吗？」（当场锁下一个时间点）

**落点**：`references/talk-tracks.md`「口头被当场否」节。

## P2：改了更好用（3 项）

### 12. 六模块输出很长，缺「见领导前 5 分钟速览卡」

六件套加起来通常 1500 字以上。但真实使用场景是：用户在会议室门口，只有 3 分钟。原提示词没有为这个场景设计产物。

补一张**速览卡**（5 行内）：主由头一句、目标数字一个、底线数字一个、必须说出口的一句、绝对不说的一句。

**落点**：`references/templates.md`「速览卡」节。

### 13. 敏感变量没有隔离规则

年龄、性别、婚育、户籍、健康状况、家庭负担——这些在真实谈判中确实影响策略（比如婚育可能被公司当作不稳定因素，家庭负担可能被当作不敢走的信号），但它们**绝对不能进入任何对外文本**：既可能构成歧视性表述，也会被对方反用。

补一条硬规则：**敏感变量只进内部判断，永不进话术。** 且当用户主动提及（「我房贷压力大」）时，Agent 要接住情绪但明确说明「这句话我不会写进邮件，它会削弱你的立场」。

**落点**：`references/guardrails.md`「敏感变量隔离」节。

### 14. 国企/体系内只说了「难」，没给路径优先级

原提示词说「受工资总额管控，直接加底薪难，优先岗位津贴、专项奖励、职级序列内微调」——方向对，但三条并列，没排序。体系内的正确顺序是：**职级序列晋升 > 专项奖励/一次性激励 > 岗位津贴 > 底薪调整**。因为职级晋升会同步拉动所有挂钩项（津贴、公积金基数、年终系数），一次动作多处生效，是性价比最高的路径。

**落点**：`references/decision-chain.md`「企业类型适配」节。

## 一句话总结这 14 项改动的方向

原提示词教 Agent **怎么说得体**；这次补的是**要多少（定价）、凭什么（取证）、不批怎么办（退路）**。得体是及格线，这三样才是谈判。

配套改动已落到本包：定价交脚本，取证交由头库，退路交复谈日历与结构收益分级。原提示词的护栏一条没删，只补了反例。
