# 涨幅定价模型：三锚定法与三档区间

原提示词反复要求「给区间」，但没给算法。这份文件补的就是算法。

**一条纪律**：所有数字由 `scripts/salary_calc.py` 算出，模型不口算区间。脚本不可用时才用手算表（本文末），并在交付里注明「本次未用脚本」。

---

## 一、为什么必须是三锚，不能是一个数

只给一个数，谈判就变成「接受或拒绝」的二选一，你必然被压。三锚的作用是**把单点谈判变成区间谈判**：

| 锚 | 是什么 | 谁说出来 |
|---|---|---|
| 开口锚 Ask | 第一次报的数，高于真实目标 | 你主动说 |
| 目标锚 Target | 你真正想拿到的值 | 不说，只用来判断对方还价是否可接 |
| 底线锚 Walk-away | 低于此值不接，改谈结构 | 不说，只在心里 |

报 Ask 不是为了拿 Ask，是为了让对方的还价落回 Target 附近。**没有 Ask，对方就从 Target 往下砍。**

---

## 二、锚 A · 内部带宽分位

### 需要的信息

带宽 `[下限 L, 中位 M, 上限 U]`。用户常不知道，可从三处推：
- 招聘 JD 上写的薪资范围（通常就是 L—U，中位是 M 的近似）
- 同岗位新人的 offer 范围（最准，但要注意保密）
- 公司薪酬制度文件或职级对照表（大公司内网常有）

### 算法

```
当前位置分位 pos = (现有薪资 − L) ÷ (U − L)
```

| pos 区间 | 定位 | 目标算法 | 配套主由头 |
|---|---|---|---|
| pos < 0.50 | 低于中位 | Target = M × 1.05 | 职级带宽内校准 |
| 0.50 ≤ pos < 0.75 | 中位到 75 分位 | Target = 现有 × 1.10 | 职责扩展 |
| pos ≥ 0.75 | 接近上限 | 底薪空间已尽，转结构收益 | 关键人才保留 + 结构收益 |

**上限硬约束**：Target 不得超过 U。超了就说明这不是加薪问题，是**职级问题**——该谈晋升，不该谈涨薪。

### 为什么低于中位时用 M×1.05 而不是 M

直接要中位，等于要求公司承认当初定级偏低，这是让人认错，阻力最大。要中位上方一点点，对方可以说「校准到中位偏上」，是个体面的说法。**给对方留台阶，是让流程能走下去的技术动作。**

## 三、锚 B · 增量产出折算

### 算法

```
目标年化增量 = 用户提供的增量收益 × 分享比例
Target(B) = 现有月薪 + (目标年化增量 ÷ 12)
```

### 分享比例（经验区间，非精确值）

| 增量性质 | 分享比例 | 理由 |
|---|---|---|
| 直接收入创造（销售、BD、投放 ROI） | 20%—25% | 归因清晰，可核算 |
| 成本节省 / 效率提升 | 15%—20% | 归因较清晰，但有协同因素 |
| 风险规避 / 客户留存 | 10%—15% | 归因难，易被质疑「本来也不会出事」 |
| 支持职能（HR、财务、行政） | 10%—15% | 间接贡献，需转成业务语言 |

**写邮件时用绝对值，不写比例。** 「带来 120 万增量，希望薪酬有相应体现」比「按 20% 分成我要 24 万」安全得多——后者会让对方立刻开始跟你算账，而算账的主动权在他手上。

## 四、锚 C · 替换成本倒推

### 算法

```
替换总成本 ≈ 现有年薪 × (replace_months ÷ 12)      # replace_months 默认 7.5，区间 6—9
Target(C) = 现有月薪 × (1 + replace_months ÷ 12 × 0.5)
```

即：公司为避免这笔替换成本，理性上最多愿意付其中一半来留人。

`replace_months = 7.5` 时，Target(C) ≈ 现有 × 1.31（+31%）。

### 使用纪律

- 这个值**是上限参考，不是建议值**。它回答的是「公司最多能忍到哪」，不是「你应该要多少」。
- 只有主由头是「关键人才保留」时才启用。
- 表达时用经济账，不用威胁：「换人大概 6 到 9 个月成本」是替公司算账；「所以你得给我涨」是替自己开价。前者有效，后者归零。

### 替换成本的三个组成（用户可自己核）

| 项 | 估算 | 说明 |
|---|---|---|
| 招聘成本 | 年薪 15%—30% | 含猎头费（20%—25%）、面试时间成本 |
| 上手期折损 | 3—6 个月产能 | 新人前 3 个月通常只有 50%—70% 产出 |
| 隐性成本 | 难估 | 客户关系断档、项目延期、团队补位加班 |

公开人力资本研究常把总替换成本估为 **6—9 个月薪资**。这是区间估计，引用时说「通常估计」。

## 五、加权与三档

### 加权规则

- **有带宽**：A 权重 0.5，B 0.3，C 0.2。缺哪锚，权重按剩余比例重分配。
- **无带宽**：B、C 各 0.5。缺一锚则单锚直用，并在输出里注明「单锚定价，区间偏保守」。
- **用户自己给了期望涨幅**：用用户的数作 Target，但必须跑匹配检查（见第六节），不匹配就提醒。

### 三档

| 档 | 算法 | 用途 |
|---|---|---|
| 开口锚 Ask | Target × ask_mult | 第一次报的数 |
| 目标锚 Target | 加权值 | 心里真实目标 |
| 底线锚 Walk-away | Target × 0.65，且不低于带宽中位 M | 低于此值改谈结构收益 |

### 开口倍数 ask_mult

| 企业类型 | ask_mult | 理由 |
|---|---|---|
| 民企 / 成长型 | 1.15—1.20 | 决策链短，会直接砍价，需留空间 |
| 外企 / 成熟体系 | 1.10 | 走带宽与分位逻辑，虚高会被判定不专业 |
| 国企 / 体系内 | 1.05 或改走津贴 | 工资总额管控，虚高无效 |
| 不确定 | 1.10 | 按流程严格型保守处理 |

**底线锚不低于带宽中位**这条很重要：如果算出来的 Walk-away 低于 M，说明 Target 定低了，应该回头调 Target，而不是接受一个低于中位的数。

## 六、匹配检查（脚本会自动跑）

| 检查 | 触发条件 | 处置 |
|---|---|---|
| 涨幅超由头上限 | 实际涨幅 > 该由头的经验上限 | 警告：换更强由头，或把超出部分转结构收益 |
| Target 超带宽上限 | Target > U | 警告：这是职级问题，不是加薪问题 |
| Walk-away 低于中位 | Walk < M | 警告：Target 定低了，回调 |
| 单锚定价 | 只有一锚可用 | 标注「区间偏保守」 |
| 涨幅低于 3% | 实际涨幅 < 3% | 提示：低于此值通常不值得消耗一次申请机会 |
| 用户期望远超上限 | 用户给的 pct > 由头上限 × 1.5 | 提示：大概率被拒，且会影响下次，建议先调预期 |

## 七、手算表（脚本不可用时）

按顺序填，五分钟能算完：

```
① 现有月薪 ____________
② 现有年薪 = ① × 12 = ____________

③ 带宽：L ______  M ______  U ______
   pos = (① − L) ÷ (U − L) = ______
   pos < 0.5  → Target_A = M × 1.05 = ______
   0.5—0.75   → Target_A = ① × 1.10 = ______
   ≥ 0.75     → 转结构收益，Target_A 不适用

④ 年化增量 ______ × 分享比例 ______ = ______
   Target_B = ① + (④ ÷ 12) = ______

⑤ Target_C = ① × 1.31 = ______（仅关键人才保留由头用）

⑥ 加权 Target：
   有带宽 → (Target_A × 0.5 + Target_B × 0.3 + Target_C × 0.2) = ______
   无带宽 → (Target_B × 0.5 + Target_C × 0.5) = ______

⑦ Ask = Target × ask_mult（民企 1.18 / 外企 1.10 / 国企 1.05）= ______
⑧ Walk = Target × 0.65，且 ≥ M = ______
⑨ 缺口 = Target − Walk = ______  ← 这个数就是结构收益要补的额度
```

第 ⑨ 行是最容易被忽略但最有用的一行：**底薪谈不下来时，结构收益不是随便要，是要补上这个缺口。**

## 八、这张表不能做什么

- 不能当市场行情用。锚 A 依赖公司自己的带宽，锚 B 依赖用户自己的产出，锚 C 依赖替换成本估算——**三个都是这家公司、这个人、这个岗位的局部值**，不是行业数据。
- 不能保证被批。它只保证一件事：**你报的数有依据，对方压价时必须给出理由。** 谈判里这已经赢了一半。
- 不能替代预算现实。公司没钱的时候，任何模型都无效，此时唯一有效的是结构收益与时间承诺。
